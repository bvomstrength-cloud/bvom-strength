# Fixed working prescriptions

The advanced lift editor and workout weight panel accept whole-number set and rep targets for eligible core lifts and Custom straight-set compounds. Bounds match the existing Custom Training builder: 1–20 working sets and 1–50 reps. Leaving the displayed default unchanged keeps the original plan. Overrides are saved per programme and lift. Custom Training uses its existing per-day compound template and keeps manual progression.

An edit uses the same numbered slots in the current workout. The first prescribed slots are evaluated against the revised rep target. Their original actual load, reps, and recorded target are preserved. Recorded slots beyond the reduced count stay visible and are included in volume and History. The existing explicit extra sets are separate from prescribed slots in the core engine. An expansion revokes a previously earned result until every newly required slot is recorded. A completed fixed prescription succeeds when all required slots reach the target. A recorded miss follows the mode’s existing failure or close-miss path. Finishing with unrecorded required slots uses the existing incomplete-workout flow.

The fixed override applies to ordinary core straight and RPT lifts in LP/RPT, HLM and 4-Day Split. Configured RPT starts with the entered targets at working weight. Overhead Press retains its ramps and backoffs, shortening the ramp if necessary to leave room for the top set. A miss uses the existing recovery planner. The drop starts from the actual load when a previously recorded set retains an earlier load after an edit. Subsequent drops round through the existing equipment constraints. The existing core result evaluator and close-miss decision still determine whether the next weight increases. If the lifter accepts the next RPT rep level after three failures, the fixed rep target drops by one for future workouts, preserving the set count. The finished attempt keeps its original target.

HLM/Split Squat and Bench retain the linked roles. The Heavy engine hard-codes the top at slot three in its planner, result evaluator, and terminal decision checks. It uses the 2–5 driver rep level to derive Light and Medium, including the Medium optional-single percentages. Arbitrary prescriptions need an agreed mapping for shorter Heavy plans and rep targets outside that driver range. Straight Deadlift at the optional-single exposure retains its existing prescription because its auto-appended single and skip action use the original working-set completion boundary. Selecting RPT for that Deadlift exposure uses the ordinary RPT engine, which already omits the optional single. Custom RPT retains its existing plan editor. Bodybuilding is outside the override.

Existing data with no override reads the original prescriptions. The core override travels with existing backup data, while interrupted workouts follow the established local-first policy. The release still needs physical Android acceptance.

## Existing RPT transition rules

The generic core planner follows the base prescription until the first recorded miss. The next working slot uses the current lift's configured percentage drop and starts at the achieved reps plus one. Each following recovery slot drops the preceding load again and rounds through the equipment rules. With two recovery slots left at the first miss, their offsets are 0 and +2. With three or more, the offsets are 0, +1, then +3. A recovery miss reduces the running target base by one for later slots. The final recovery slot is AMRAP. The existing result evaluator treats a top or pre-top miss as failure and a backoff-only miss as a close miss, which offers the existing repeat/progress decision. A strong recovery AMRAP does not turn a failed top set into automatic progression.

Heavy HLM and Split use a different planner. The third working slot is the top set, preceded by two ramps. Top and pre-top performance drives the next Heavy load. Light and Medium derive their loads from that Heavy driver, and Medium can offer a linked optional single. Custom Training RPT has static templates and manual progression; it does not call the core recovery engine.
