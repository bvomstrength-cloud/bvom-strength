# v3.0.3 working weight display candidate

Baseline: verified fetched `origin/main` at v3.0.2 `2e93b4dbb098bba4a4e8bba23b9451449a9e20f9`.
Dedicated branch: `fix/v3.0.3-working-weight-display`. Draft review and separate Netlify test ZIP only; no merge or production deployment.

## Change and programme audit

The shared LP/RPT, HLM and 4-Day card renderer read a weight that the engine could already have advanced. It now uses the existing durable pre-progression snapshot for the large current weight. Logged set actuals, prescription and progression functions remain untouched. The weight dialog opens with that same current/top weight (including RPT Press, where the first set is lighter than the top).

A small EN/JA future label appears only for a processed lift with a saved, changed next load and no pending choice or explicit future configuration override. Failed attempts without a changed confirmed load show no prediction. Confirmed resets may show a lower next load. An unresolved third-failure dialog is excluded by its existing failure threshold. HLM Heavy says `Next Heavy workout`; Split Heavy names workout 1 (Bench) or 2 (Squat). Light and Medium show their calculated session load and no future prediction. Ordinary independently progressing lifts can show their confirmed next exposure load.

Manual card weight edits retain existing behaviour and remain visible before/after completion and reload. Existing Advanced Settings prescription locks continue to define which edits apply to the current versus future workout. Corrections withdraw/recompute progression through the unchanged engine. Extras cannot become the current top load or confirm progression.

BB1, BB2 and Custom use separate renderers. BB1 progression is committed at Finish and its current card labels were previously repaired. BB2 uses its active session/preview adapter; Custom has no automatic progression. No changes to their renderers or training engines are needed.

No changes to progression calculations, targets, failure counts, deloads, HLM drivers, RPT back-offs, completion criteria, extras, History/backup formats, cloud transport or schemas. Version/cache markers identify the v3.0.3 candidate.
