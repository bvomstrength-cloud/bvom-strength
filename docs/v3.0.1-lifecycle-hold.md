## Repair

`bvomStateWorkoutActive` remains strict: timestamps, actuals, GPP and BB2 active IDs continue to protect restore. The fix removes only a proven orphan timestamp instead of teaching restore to ignore it.

`bvomEmptyTimestampSession` accepts only current-ownership protocol states, supported programmes, a numeric positive timestamp and explicitly empty session shapes. Zero-rep rows, Custom optional singles, unknown rows, GPP, processed state/snapshots, overrides, warm-up ticks, pending LP/HLM/BB1/On-Ramp decisions, deferred setup, notes, pending future deletions and meaningful Custom drafts prevent cleanup. An unchanged Custom draft copied from the current day is recognised as empty. BB2 active/open sessions never qualify; idle ledger records are retained byte-for-byte as a subtree. Ambiguous/malformed shapes fail closed.

Custom's two set-removal entry points and BB1's prescribed/extra-set REMOVE now use one durable mutation for removal plus eligible timestamp cleanup. Failed writes restore memory and preserve stored work. A remaining set keeps the workout active.

The existing recovery path clears owned orphan states without waiting for age, adding History or invoking progression. Both saved and in-memory states must qualify and retain the same cloud-comparable content. Current account, Web Lock, workout-tab marker and exact raw-storage checks are rechecked at the write. Pre-ownership legacy states retain the existing read-only/archive escape; they are never cleaned automatically.

BB2 shows **CANCEL WORKOUT** only after an explicit empty Start. Confirmation captures the raw document/account/tab/session token. `bvomBb2Discard` itself refuses prescribed or extra working-set events regardless of rep count, validates the current ledger, compares memory with the saved BB2 subtree and repeats the unchanged-context checks after planning. Double taps and stale callbacks cannot cancel newer work. The frozen discard/tombstone engine is reused unchanged. Setup, future edits, quotas, progression and History are retained; the same workout can restart.

Cloud/file restore guards, cloud comparison normalization, revision/baseline transport, storage keys, backup formats and all prescription/progression/ledger modules are unchanged.
