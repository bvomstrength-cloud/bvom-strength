# v3.0.2 optional extra working sets (development)

Baseline: production `main` v3.0.1, `b990d8385e2e4dc57ceea859994f11c9b7d756fa`.
No merge, release or production deployment is authorized.

LP/RPT, HLM and 4-Day main exercises offer **+ ADD EXTRA SET** (English/Japanese), with positive actual weight and whole reps including zero. Like BB1, the dialog suggests the preceding recorded actual load, or the last planned load before any actual exists. Record, edit and remove operate on actuals only. Each exercise allows up to 30 extras.

Strength extras live under `session[lift]['EXTRA:n'] = {load,reps,extra:true}`. Existing numeric indices remain exclusively owned by the current prescribed plan, including dynamic rescue sets and optional singles. Prescribed-set correction clears dependent numeric indices but retains extras. HLM's queued Heavy target/activation explicitly tests numeric indices so an earlier extra cannot consume or hide the next Heavy prescription. No new progression engine or programme configuration is introduced.

The existing set markup, History extra labels, volume calculation, durable save/removal, unit conversion, inactive recovery, completed History transport and backup format are reused. Extra edits recheck account, units, programme/day, session identity and exact stored document before committing. Failed durable writes restore memory. BB1, BB2, Custom, BB2 Start, Supabase schemas, subscriptions and cloud conflict guards are unchanged.

Active sessions follow the existing local-only cloud policy; completed History (including extras) syncs normally. Backup exports retain active actuals. No cross-device resumption of an active workout is added.
